The fleet design for hundreds of people and repositories

OIDC/mTLS caller -> signed team catalog -> team cell -> bounded scheduler -> one repository actor -> terminal Beads UOW -> Dolt primary/standby -> canonical receipt + outbox
  • Base shard: one Dolt database per repository. A signed catalog maps team_id + repository_id to one cell/database and carries catalog, database, producer and key epochs.
  • Team isolation: do not merely share logical queues. Give a team a cell/failure-domain budget, unique workload credentials, queue and pool quotas, then compare quiet-team p95 against its isolated baseline. The current catalog model still permits shared endpoints, so physical isolation is a design requirement, not a proven property.
  • Cold fleet: zero connections for idle repositories; lazily create one serial repository actor. Per cell, use 28 resident application leases and Dolt max_connections=32, reserving four control/drain slots.
  • Hot ae: use a dedicated gateway cell and dedicated Dolt pair first. The measured single database met the original p95 criteria; sharding it now would create cross-shard claim, hierarchy, dependency-cycle and restore invariants without evidence of need.
  • If ae later fails: shard only by a stable ownership key that keeps issue, claim, hierarchy and write dependencies local (for example, durable workstream home). Global search/reporting becomes an eventual projection; cross-shard dependencies need an explicit coordinator and reconciliation log.

Realistic concurrency, not a land-speed stunt

The frozen model accounts for LLM latency, agent think time, human cognitive load and a few concurrent agents per person: about 0.98 commands/s normal, 7.90/s busy, and a coordinated 34.09/s burst. One 120-second busy run delivered 8.33/s; one burst delivered 35.23/s. Exact independent effects passed on two databases.

Truth boundary: those runs used the legacy operations lane, only two databases/two destination teams, and one window each. Their JSON says capacity_promotion_eligible=false. They prove an SLO/exact-effect subset, not 300-person identity, terminal durability, recovery, utilization or fleet capacity. Burst create p99 was 3.24 s and max 4.81 s, exposing head-of-line tail risk.

Good, bad, ugly, and dogs not barking

Good

Near-data latency; deterministic terminal IDs; one canonical Dolt receipt/outbox; queue-loss rebuild; real two-process CAS hard caps; fail-closed cluster warning handling; bounded connection pool; focused tests/race/vet.

Bad

Components are not integrated. The Beads UOW patch covers update, heartbeat and ready/claim but leaves 18 same-UOW commit retry callers. Current safety changes postdate historical performance evidence.

Ugly

Dolt SELECT FOR UPDATE is ineffective here; use a versioned UPDATE CAS ledger. Replication timeout is SQL warning 3024, not an error. A 503 means unknown: retry the same key/body, never compensate with a new key.

Dogs not barking

No multi-zone partition/RTO, old-snapshot restore, 300 principal revocation, physical team bulkhead proof, durable outbox consumer/DLQ, schema/rolling upgrade, disk-full/KMS/clock-skew, or 24-hour RSS/history/GC plateau.

Locks, data damage, reconciliation and recovery

  • Conflicts: Dolt optimistic writers can return 1213. Retry the entire high-level operation from a fresh UOW/snapshot, never only DOLT_COMMIT. Serialize one repository actor and use CAS for shared capacity counters.
  • Partial graphs / lost edges: validate DAG in memory, perform nodes and edges in one transaction, commit one canonical outcome, and independently inspect issue/event/dependency/commit counts. Failure must leave zero graph state.
  • Duplicate claims: subject-bound deterministic operations plus one atomic claim UOW; no same-key body change; audit one claim event and one commit.
  • Ambiguous response: 503 + Retry-After; retry identical key/body. The gateway reads canonical Dolt first. A local queue is a projection and can be rebuilt. Persistent failures stop after three tries; retained source caps terminal projection at 20,000 rows/128 MiB and retry-exhausted projection at 100.
  • Retention/restore: watermark compacted sequences, rotate producer/database/key epochs, and keep the newest catalog watermark in a stronger control plane that does not roll back with the cell. The real-Dolt CAS proof passed; an actual old-backup restore remains required.

Recommendation and the next experiment

Build one converged "epoch-fenced repository cell"; do not deploy the current fork. This is a new synthesis for this environment, not a claim of global invention: terminal high-level Beads operations, a stronger monotonic routing watermark, per-repository actors, bounded fair admission, lazy 28/32 pools, canonical CAS retention, subject identity and cluster acknowledgement.

  1. Wire terminal-v2 only + the complete Beads fresh-UOW kernel + signed catalog/watermark + scheduler + lazy pools + CAS retention + cluster guard in one binary. Add OIDC/mTLS identities and per-team secrets/quotas.
  2. From a committed source/binary manifest, run five busy and three burst windows at 150 ms across at least 100 real repo DBs, 30 team/principal identities and dedicated ae. Mix create/update/close/claim/batch/dependencies/hierarchy/graph; enforce ordinary p99 under 3 s and quiet-team p95 no worse than 1.25x isolated.
  3. Use two gateway peers and two physically separate Dolt nodes. Kill/partition at admission, mutation, outcome commit, replication barrier, response, projection loss, promotion and same-key retry.
  4. Restore an older backup; advance catalog/database/producer/key epochs; inject stale queues/workers; prove every stale request is fenced with no phantom success.
  5. Run 24 hours or one million fixed-cardinality mixed operations. Gate RSS, heap, FDs, connections, queues, receipts, dead letters, outbox, Dolt history, barrier commits, disk and GC on plateaus.

This convergence needs a new cost/isolation approval because the approved lab had one VM; physically separate failure domains cannot honestly be simulated on it.

Migration, rollback, cost and ownership

  • Migrate: shadow reads -> duplicate terminal decisions without writes -> canary one team -> dedicated ae -> team cells. Keep direct embedded/co-located mode unchanged.
  • Rollback: stop gateway admission, drain terminal operations, verify canonical receipts/outbox, return clients to embedded/local sync. Never roll back catalog/database epochs or reuse retired producer/key epochs.
  • Operations: a gateway adds identity, certificates, routing, queue/dead-letter, backup, failover and on-call burden. That burden is justified only because it removes the structural WAN floor and provides one enforceable correctness boundary.
  • Cost: the disposable peng-os e2-standard-2/50 GB lab was about $0.074/hour compute and remained below the approved envelope. It is now TERMINATED; the boot disk is preserved with automatic deletion scheduled for 14 July. The rate is an estimate, not a billing assertion.

Audit appendix: baseline, scope, tests and promotion decision

Goal contract and search surface

Objective: routine p95 below 1.5/2/3 seconds and 100/200 graph below 60 seconds at 150 ms, with atomic rollback, unique claims, intact edges, recovery and eight-writer correctness. Search covered connection/auth, discovery/probes, query count/N+1, graph algorithms/bulk work, commits/GC, daemon/pool, gateway, async outbox, Dolt sizing, catalog/scheduler, retention, HA, restoration and sharding.

Testing scorecard

Gateway full unit and race suites pass; all script packages except three realistic-fleet httptest cases pass normal/race; those three are blocked by sandbox loopback-bind EPERM, not assertions. All-script vet passes. Focused direct-provider/UOW tests and race/vet pass. The upstream-wide suite is not claimed: Docker/testcontainers and loopback constraints prevented completion.

Promotion decision

HOLD production and merge of the broad lab. Promote only the architecture verdict, authoritative retention CAS oracle, and small reviewable UOW pieces. Historical gateway metrics remain architecture evidence until the current committed source is rerun.

Risks and follow-up evaluation

Highest risks are identity revocation, stale control-plane rollback, cross-team noisy neighbors, failover epoch automation, terminal inspector exactness, outbox delivery, long-term history/memory and operator complexity. The five-step convergence experiment is the trace-to-evaluation follow-up.

Architecture decision record and rejected alternatives

Decision: high-level near-data terminal service. In scope: Beads semantics, one repo DB, team cell, deterministic recovery. Out: orchestration policy in Beads core, global graph sharding before need, production deployment.

Rejected: direct WAN SQL tuning as final answer; workstation daemon; local-queue 202 authority; fixed warm pool per repo; 1 GiB Go limit; disabling auto-GC; immediate ae sharding; unsafe global-role cluster harness; claiming separate prototypes form a fleet.

Confidence: high that a near-data boundary is required; medium that the decomposed mechanisms converge without another redesign; low that production readiness can be inferred from current evidence.

Code-review and upstream boundary

The UOW Draft preserves upstream PR #4675 contributor history. Focused fixes are transaction cleanup, fresh-snapshot retry, heartbeat parity and atomic ready/claim. Eighteen callers remain. The gateway branch is a fork-only lab Draft, does not supersede upstream PRs #3458, #4167 or #4581, and is not suitable as one broad upstream PR.
